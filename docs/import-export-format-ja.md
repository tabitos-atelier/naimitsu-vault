# エクスポート・インポート フォーマット仕様

<p align="center">
  <strong>日本語</strong> | <a href="import-export-format.md">English</a>
</p>

ないみつクンの暗号化なしエクスポート・インポート機能が扱うデータ形式の仕様書です。
他のパスワードマネージャーからの移行コンバータを作成したい方はこの仕様を参照してください。

> **注意:** プロフィール管理データ（マイナンバー・パスポート番号・免許証番号等）はセキュリティ上の理由から暗号化なしエクスポートの対象外です。

---

## 共通事項

* 文字コード（エクスポート）: **UTF-8**（CSV は BOM 付き・JSON は BOM なし）
* 文字コード（インポート）: 上記の出力形式は入力の必須条件では**ない**。CSV・JSON とも **BOM の有無を問わない UTF-8** と、**BOM 付きの UTF-16 LE/BE**（UTF-8 へ自動変換される）を受け付ける。それ以外は非対応で、UTF-32 や有効な UTF-8 でないファイル（Shift_JIS などの ANSI コードページ）はレコードを1件も取り込む前にエラーとして拒否される。UTF-16 は BOM がある場合のみ認識される。コンバータは UTF-8 で出力すること
* 日時の形式は JSON と CSV で異なる。**JSON** は ISO 8601 形式（UTC オフセット付きのローカル時刻。例: `2026-01-01T09:00:00+09:00`。入力でオフセットを省略した場合はローカル時刻として扱う）、**CSV** は `yyyy-MM-dd HH:mm:ss`（有効期限のみ `yyyy-MM-dd`。タイムゾーン情報なしのローカル時刻）で出力・入力する
* `null` フィールドは空文字またはフィールドごとのデフォルト値として扱われる
* `totpSecret`（および `totpDigits`/`totpPeriod`/`totpAlgorithm`）の**出力**は設定画面の「2FA シークレットを含める」トグルが **ON** の場合のみ（デフォルト OFF）。このトグルは**エクスポート専用**で、**インポート**側には対応するトグルが存在せず、ファイルに `totpSecret` が含まれていれば常に取り込まれる

---

## JSON 形式（推奨）

TOTP シークレットを含めて移行する場合は JSON 形式を使用してください。

### 構造

```json
[
  {
    "title":        "GitHub",
    "category":     1,
    "userId":       "tabito",
    "password":     "KJdWe%oLu7C$vlhjMBa#",
    "website":      "https://tabitos-voyage.com",
    "email":        "tabito@example.com",
    "notes":        "メモ",
    "customFields": [
      { "Label": "備考", "Value": "テスト", "FieldType": 0 }
    ],
    "createdAt":    "2026-01-01T09:00:00+09:00",
    "updatedAt":    "2026-03-15T12:34:56+09:00",
    "isFavorite":   true,
    "expiresAt":    "2027-01-01T00:00:00+09:00",
    "totpSecret":     "JBSWY3DPEHPK3PXP",
    "totpDigits":     8,
    "totpPeriod":     30,
    "totpAlgorithm":  "SHA256"
  }
]
```

### フィールド定義

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `title` | string | タイトル。インポート時は前後の空白を除去する |
| `category` | number / null | カテゴリコード（下記「カテゴリコード」参照）。`null`・省略時は未設定のまま |
| `userId` | string / null | ログインID（ユーザー名） |
| `password` | string / null | パスワード |
| `website` | string / null | Web サイトの URL |
| `email` | string / null | メールアドレス |
| `notes` | string / null | メモ。インポート時に改行コードは LF に統一される |
| `customFields` | array / null | カスタムフィールドの配列（構造は次節） |
| `createdAt` | ISO 8601 | 作成日時。省略時はインポート実行時刻 |
| `updatedAt` | ISO 8601 | 更新日時。省略時はインポート実行時刻 |
| `isFavorite` | boolean | お気に入りフラグ（省略時 `false`） |
| `expiresAt` | ISO 8601 / null | 有効期限。`null`・省略時は期限なし |
| `totpSecret`     | string  | Base32 のシークレット本体（下記「`totpSecret` の形式」参照）。トグル ON 時のみキーを出力。OFF 時はキーごと省略 |
| `totpDigits`     | number  | コード桁数（6〜8）。省略時は `6`。既定値どおりの場合は出力自体を省略する |
| `totpPeriod`     | number  | 更新周期・秒（RFC 6238 既定値 `30`）。省略時は `30`。既定値どおりの場合は出力自体を省略する |
| `totpAlgorithm`  | string  | ハッシュアルゴリズム。`"SHA1"`（既定）/`"SHA256"`/`"SHA512"`。省略時は `"SHA1"`。既定値どおりの場合は出力自体を省略する |

型に `/ null` とあるフィールドは、エクスポート時に値が無いと `null` が出力され、インポート時も `null` または省略が許容される。

### `totpSecret` の形式

* 値は **Base32 のシークレット本体**（RFC 4648 の文字集合: `A`〜`Z` と `2`〜`7`）。`otpauth://` URI では**ない**。移行元のパスワード管理アプリがシークレットを URI で出力する場合は、コンバータ側で `secret` パラメータを取り出し、`digits`・`period`・`algorithm` を `totpDigits`・`totpPeriod`・`totpAlgorithm` へ対応付けること。
* インポートはこの文字列を正規化も検証もせず、与えられたまま保存する。コード生成時には小文字・空白・`=` パディングが許容されるが、それ以外の文字が含まれるとアプリはその項目のコードを生成できない（項目自体は取り込まれる）。確実に動作させるため、コンバータは大文字・空白なし・`=` パディングなしで出力すること。

### `customFields` の構造

```json
[
  {
    "FieldId":   1,
    "Label":     "フィールド名",
    "Value":     "値",
    "FieldType": 0
  }
]
```

`FieldType` は整数（文字列ではない）。`0` = テキスト（既定）、`1` = パスワード、`2` = URL、`3` = 日付。

> キー名は PascalCase が標準です。インポート時は大文字・小文字を区別しません。
> `FieldId` が `0`・非数値・省略のいずれかの場合、**インポート処理の中で即座に**（既存の最大 `FieldId` の次番から）自動採番されます。アプリ内で編集するまで採番が遅延するわけではありません。

## CSV 形式

> **注意:** CSV 形式は `totpSecret` に対応していません。TOTP を含めて移行するには **JSON 形式**を使用してください。

### ヘッダー行

```
Title,Category,UserId,Password,Website,Email,Notes,CustomFields,CreatedAt,UpdatedAt,IsFavorite,ExpiresAt
```

### 列定義

| 列 | 型 | 備考 |
| --- | --- | --- |
| Title | string | 前後の空白を除去して扱う。空でもレコードは取り込む（タイトルが空の項目になる）。ただし全列が空の行は無視する（下記） |
| Category | integer | 空または数値以外は未設定（`null`）。現在のプリセットに無いコードは `0`（未分類） |
| UserId | string | 空の場合は未設定 |
| Password | string | 空の場合は未設定 |
| Website | string | 空の場合は未設定 |
| Email | string | 空の場合は未設定 |
| Notes | string | 空の場合は未設定 |
| CustomFields | JSON string | 空の場合は未設定 |
| CreatedAt | `yyyy-MM-dd HH:mm:ss` | ローカル時刻。空または形式が一致しない場合はインポート実行時刻 |
| UpdatedAt | `yyyy-MM-dd HH:mm:ss` | ローカル時刻。空または形式が一致しない場合はインポート実行時刻 |
| IsFavorite | boolean（`true` / `false`） | 大文字・小文字は区別しない。空またはそれ以外の値は `false` |
| ExpiresAt | `yyyy-MM-dd` | ローカル日付。空または形式が一致しない場合は期限なし |

行の列数が足りない場合、不足している列は空として扱われる。すべての列が空、または空白のみの行（空行や `,,,,` のようなカンマだけの行）は、空行として無視される。

### 記述例

上記の JSON 例と同じレコード（12 列）。`CustomFields` は JSON 配列を文字列として持つため、セル全体をダブルクォートで囲み、内部の `"` はすべて `""` に二重化する。`FieldId` は省略できる（インポート時に自動採番される）。

```csv
Title,Category,UserId,Password,Website,Email,Notes,CustomFields,CreatedAt,UpdatedAt,IsFavorite,ExpiresAt
GitHub,1,tabito,KJdWe%oLu7C$vlhjMBa#,https://tabitos-voyage.com,tabito@example.com,メモ,"[{""Label"":""備考"",""Value"":""テスト"",""FieldType"":0}]",2026-01-01 09:00:00,2026-03-15 12:34:56,true,2027-01-01
```

### エスケープ規則

* `,`・`"`・改行を含むフィールドはダブルクォートで囲む
* フィールド内の `"` は `""` にエスケープする
* **数式インジェクション対策（エクスポートのみ）**: `Title`・`UserId`・`Password`・`Website`・`Email`・`Notes`・`CustomFields` のいずれかの値が `=`・`+`・`-`・`@` で始まる場合、Excel 等の表計算ソフトが数式として実行してしまうのを防ぐため、ダブルクォートで囲んだ上でその内側先頭に半角アポストロフィ（`'`）を1文字挿入する（例: `=SUM(A1)` → `"'=SUM(A1)"`）。**値そのものが変化する**点に注意。インポート側にこのアポストロフィを取り除く処理は無いため、エクスポート→インポートを繰り返すとアポストロフィが値に残り続ける。JSON 形式にはこの処理がない（`totpSecret` を含む移行では JSON 形式の使用を推奨）

## カテゴリコード

カテゴリはアプリ内に専用テーブルを持たず、ロケール JSON（`locale-ja.json`/`locale-en.json`）の `Categories.NN`（**2桁の連番キー**）が唯一の情報源です。有効なコードの集合は固定ではなく、カスタムロケールでコードの追加や既存コードの名前変更ができます（[ロケールの README](locale/README-ja.md) を参照）。以下は既定（日本語ロケール）のセットです。

| コード | 意味       |
| --- | -------- |
| `1` | ログイン     |
| `10` | IT・インフラ |
| `20` | ライセンス   |
| `30` | プロジェクト  |
| `40` | 教育・自己研鑽 |
| `50` | 金融・カード  |
| `60` | 身分証     |
| `70` | 契約・文書   |
| `80` | 会員・生活   |
| `90` | 秘密のメモ   |
| `99` | その他     |
| `0` | 未分類（削除不可・システム受け皿） |

インポート先の現在のカテゴリプリセット（＋`0`）に存在しないコードは `0`（未分類）に自動振り分けされます。

> **注意（2026-08-19 以前の旧仕様）**: 本仕様書は過去に `1100`＝ログイン、`9000`＝未分類 のような **4桁整数** のコード体系を掲載していましたが、2026-08-19 のカテゴリプリセット再編で上記の2桁連番体系に置き換わっています。旧4桁コードで生成した JSON をインポートすると、現行のプリセット集合に一致しないため全件が「未分類」に丸められます。移行コンバータは必ず現在のロケール JSON の `Categories.NN` キー（またはアプリの設定画面で表示される値）からコードを取得してください。

## インポート時の挙動

| 状況 | 処理 |
| --- | --- |
| タイトルが既存と重複（大文字・小文字を区別しない） | ` (インポート)` を付与してリネーム。さらに重複する場合は ` (インポート2)`、` (インポート3)` …（下記の注参照） |
| タイトルが空・`null`・省略、または空白のみ | スキップせず、タイトルが空のレコードとして取り込む（データを取りこぼさないため）。空タイトルが重複した場合も通常どおりリネームされる（2件目以降は先頭が空白の ` (インポート)`） |
| CSV の全列が空（空行・カンマだけの行・空白だけの行） | 空行として無視する（レコードとして数えない） |
| カテゴリコードが現在のプリセットに存在しない（値が指定されている場合） | `0`（未分類）に振り分け。カテゴリ自体が省略された場合は `null` のまま |
| `createdAt` / `updatedAt` が省略      | インポート実行時刻を使用                                  |
| `totpSecret` あり                    | 形式・トグルの有無に関わらず常に取り込む（インポート側に「2FA を含める」相当のトグルは存在しない） |
| `totpDigits`/`totpPeriod`/`totpAlgorithm` が省略 | それぞれ `6`/`30`/`"SHA1"`（RFC 6238 既定値）を使用 |
| `customFields` が array・object 以外の型 | null として保存                                    |

> 重複時に付与される語は、インポート実行時に選択中の UI 言語の `Common.Import` の値です（日本語: `インポート`、英語: `Import`。カスタムロケールでは異なる語になります）。2件目以降は、語の直後にスペースなしで番号が続きます（`(インポート2)`）。
