# 言語 — カスタムロケール

<p align="center">
  <strong>日本語</strong> | <a href="locale-guide.md">English</a>
</p>

このフォルダには、ないみつクンで使えるカスタムロケール（言語・世界観テーマ）のサンプルが入っています。

カスタムロケールの用途は大きく2つあります。

1. **多言語対応** — 標準の英語・日本語以外の言語（フランス語・中国語・スペイン語など）をアプリに追加する。ロケールファイル（JSON）の文言をすべて目的の言語へ翻訳し、インポートするだけで、その言語のUIとしてそのまま動作します。
2. **世界観テーマ** — 方言・業界用語・ゲーム風の言い回しなど、言語は変えずに言葉遣いだけを自由にカスタマイズする（後述の「サンプルファイル」はこちらの例）。

どちらもファイル形式・インポート手順は完全に同一です。以下の説明はこの2つの用途に共通します。

## 使い方

1. 使いたい `.json` ファイルを手元に保存する
2. ないみつクン → 設定 → 言語 → **「インポート」**
3. 次回起動時から反映される

## 自作ロケールの作り方

### 1. 雛形をエクスポートする

設定 → 言語 → 「エクスポート」 で現在の言語（日本語または英語）の JSON がエクスポートされます。

### 2. JSON を編集する

> ⚠️ **【重要】文字コードについて**
> 編集・保存する際は、必ず **「UTF-8」** で保存してください。それ以外の文字コードで保存されたファイルはインポートできません。

```json
{
  "locale": "ja",
  "displayName": "あなたのテーマ名",
  "localeVersion": 1,
  "messages": {
    "Common": {
      "#01-01: 共通操作": {
        "Ok": "変更したいボタンの文言",
        "Cancel": "変更したいボタンの文言"
      }
    },
    "Unlock": {
      "#02: ロック解除": {
        "Main": "変更したいボタンの文言"
      }
    },
    "TimeMachine": {
      "#07: タイムマシン": {
        "Dialog": {
          "PurgeConfirmText": "変更したいダイアログの文言"
        }
      }
    }
  }
}
```

上記は読みやすさのため一部だけを抜粋した例です。実際にエクスポートされるファイルには全キーが、これと同じ階層形式で含まれています。

| フィールド           | 説明                                 |
| --------------- | ---------------------------------- |
| `locale`        | 基底言語コード（`"ja"` または `"en"`）。全く新しい言語（フランス語など）を作る場合も、雛形として近い方（文構造・敬語の有無など）を選んでください。不足キーの自動補完や `{0}` 個数チェックにこの基底言語が使われます |
| `displayName`   | 設定画面に表示される名前（テーマ名、または言語名そのもの）      |
| `localeVersion` | エクスポートされた値をそのまま入れてください             |
| `messages`      | キーと文言のペア（変えたい箇所だけでOK、不足分は自動補完されます） |

### キー命名規則（読むだけでOK）

キーはドット区切りの文字列ではなく、JSON オブジェクトの入れ子（階層構造）で整理されています。各文言は次の階層の最下層にあります。

```
messages                          ← ルート
└─ ドメイン                        ← オブジェクト：機能領域（Common / Unlock / Shell / Secrets / Totp など全17種）
   └─ "#NN-NN: セクション名"       ← オブジェクト：セクショングループ（人が見通すための見出し）
      ├─ 識別子                    ← 文字列：文言そのもの（Ok / Cancel / GeneralError など）
      └─ サブドメイン              ← オブジェクト：表示形態（Dialog:モーダル / Navi:ナビゲーション）※省略可
         └─ 識別子                 ← 文字列：文言そのもの
```

- **ドメイン** — `messages` の直下にある最上位のキーです。（アプリ内部用の `System` ドメインはエクスポートされず、インポートするファイルに含まれていても無視されます。）
- **セクショングループ** — ドメインの中の `#` で始まるキー（例: `"#01-01: 共通操作"`）です。関連する文言をまとめる見出しにすぎません。アプリはグループ名を無視するため、キーの一部にはならず、**翻訳・変更の対象外**です。
- **識別子** — 値が文言になっているキーです。**名前は変更せず**、値だけを書き換えてください。
- **サブドメイン** — セクショングループの中に置かれる省略可能なオブジェクト（`Dialog` / `Navi`）で、その表示形態の識別子をまとめます。

例: `TimeMachine` → `"#07: タイムマシン"` → `Dialog` → `PurgeConfirmText` = タイムマシンドメイン(TimeMachine) / モーダル(Dialog) / 完全削除の確認文言(PurgeConfirmText)
例: `Common` → `"#01-01: 共通操作"` → `Ok` = 全画面共通ドメイン(Common) / サブドメインなし / OK ボタン(Ok)

エクスポートされた構造はそのまま保ってください。アプリはドメイン・サブドメイン（あれば）・識別子の組み合わせで文言を特定するため、各識別子が元のドメイン（およびサブドメイン）の下にあることが重要です。

### カテゴリ（`Categories` ドメイン）

`Categories` ドメインは上記の命名規則の唯一の例外で、識別子が英語名ではなく **2桁のカテゴリコード**（`01`〜`99`）になっており、値がアプリに表示されるカテゴリ名です。カテゴリを定義する別の設定は無く、このドメインがカテゴリの唯一の定義場所です。

```json
"Categories": {
  "#11: カテゴリ": {
    "01": "ログイン",
    "10": "IT・インフラ",
    "15": "ゲーム",
    "Uncategorized": "未分類"
  }
}
```

上記は抜粋で、`15` は新しく追加したカテゴリの例です（既定のセットには含まれません）。

- **カテゴリ名を変える** — 値を書き換えます。
- **カテゴリを追加する** — ちょうど2桁の数字のキーを新しく追加します。カテゴリはコードの昇順で並ぶため、既定のコードは `01`・`10`・`20`… と間隔を空けてあり、その間（`15` など）に自作のカテゴリを差し込めます。
- **既存カテゴリのコードは変更しないでください。** 各項目が保存しているのは名前ではなくコードです（[エクスポート・インポートのファイル](import-export-format-ja.md)に出てくるのもコードです）。定義されなくなったコードを持つ項目は**未分類**として表示されます（保存データ自体は書き換えられません）。
- **ファイルからカテゴリを削除しても反映されません。** ファイルに無いキーはインポート時に基底言語（`locale`）から補完されるため、既定のカテゴリが復活します。行えるのは追加と名前の変更のみです。
- **`Uncategorized`** はコード `0`（カテゴリ未設定の項目）用の固定キーで、このドメインで唯一の数字ではないキーです。文言は変更できますが、削除や番号の変更はできません。`00` のキーは追加しないでください。
- カテゴリとして扱われるのは、ちょうど2桁の数字のキーだけです。`1`・`100`・`AB` などのキーはカテゴリとして扱われません。

### `{0}` プレースホルダー

文言に `{0}` `{1}` が含まれている箇所は動的な値が埋め込まれます。**そのまま残してください。**（文中での位置は自由に動かせます）

`{0}` などを削除したり、書式を壊したり（`{` の閉じ忘れなど）すると、画面表示の不具合を防ぐため、**その項目だけ自作の文言が反映されず、基底言語（`locale` で指定した日本語または英語）の標準の文言に置き換わります**。他の項目は通常どおりインポートされます。

```json
"SuccessExportedToPath": "「{0}」の羊皮紙に刻みました。"
```

### 長すぎる文言

ボタンやダイアログから文字があふれるのを防ぐため、**UTF-8 で 120 バイト以上**（日本語で約 40 文字以上）**かつ基底言語の文言の 2 倍以上の長さ**になる文言も、インポート時に基底言語の文言へ置き換わります。通常の長さの文言には影響しません。

## アイデア例（世界観テーマ）

| テーマ         | 内容                                      |
| ----------- | --------------------------------------- |
| 関西弁         | 「ほな削除しまっせ」「保存できたで！」                     |
| 子ども向けヒーロー   | 「その呪文の長さでは敵を倒せないぞ！」— セキュリティを遊びながら学べる    |
| スペースオペラ風 | 「その合言葉では宇宙船のシールドが持ちません！」 |
| ガチャゲーム風     | 「パスワードがSSRに昇格しました！」                     |
| 丁寧語バイト敬語    | 「こちら削除の方、よろしかったでしょうか？」                  |

JSON なので AI に「〇〇風に書き直して」と頼むだけで雛形が完成します。多言語対応（フランス語版など）を作りたい場合も同様に、AI に「このJSONをフランス語へ翻訳して」と頼むだけで下訳が作れます。
